# Разведочный и визуальный анализ данных — учебные проекты

Два самостоятельных исследовательских проекта, выполненных по курсу
**«Разведочный и визуальный анализ данных»** (2 курс). Автор: Лизун Артемий.

## Проекты

### 1. `HousingPrices.ipynb` — анализ цен на жильё

Разведочный и визуальный анализ [Housing Prices Dataset](https://www.kaggle.com/datasets/yasserh/housing-prices-dataset)
(545 объектов недвижимости, 13 признаков: площадь, спальни, ванные,
этажность, удобства, статус меблировки и т.д.).

Что внутри: очистка и приведение типов, диаграммы размаха, столбчатые
диаграммы, гистограммы, тепловая карта корреляций, диаграмма Парето,
диаграмма рассеяния с линией регрессии, стебле-листовые диаграммы,
параллельные координаты, отношение шансов (логистическая регрессия),
визуализация на основе глифов (лица Чернова), асимметрия и эксцесс
распределений, меры центральной тенденции и разброса (среднее,
медиана, мода, гармоническое/геометрическое среднее, STD/MAD/IQR),
проверка нормальности (тест Шапиро-Уилка), t-тест/тест Манна-Уитни
для сравнения цен домов с парковкой и без, доверительные интервалы,
Cohen's d.

### 2. `Finale.ipynb` — факторы дефолта заёмщиков

Разведочный анализ [Credit Risk Dataset](https://www.kaggle.com/datasets/laotse/credit-risk-dataset)
(имитация данных банка о заёмщиках и кредитах) с целью выявить ключевые
факторы дефолта и предложить рекомендации по управлению кредитным
риском.

Что внутри: очистка данных и удаление аномалий, корреляционный анализ,
диаграмма Парето по классам кредита, тепловая карта дефолта по типу
жилья и долговой нагрузке, проверка четырёх гипотез (тесты
Манна-Уитни, хи-квадрат, отношение шансов), кластеризация заёмщиков
(K-Means, 4 кластера) с диаграммой параллельных координат и итоговой
сводной таблицей по кластерам, практические рекомендации по
кредитной политике.

## Что было доработано при подготовке к публикации

Ноутбуки оптимизированы (убраны пустые/дублирующиеся ячейки), а также
исправлено несколько содержательных ошибок:

- **`HousingPrices.ipynb`, диаграммы «Есть ли …?»** — `yes`/`no` в этих
  столбцах к этому моменту уже были переведены в 0/1 (см. ячейку с
  `.map({'yes': 1, 'no': 0})` выше по коду), поэтому попытка подписать
  бары через `.replace({'yes': 'да', 'no': 'нет'})` ничего не находила
  и молча не срабатывала — бары подписывались как «0»/«1» вместо «да»/
  «нет». Исправлено на `.map({0: 'нет', 1: 'да'})`.
- **`HousingPrices.ipynb`, подписи осей с ценой** — в большинстве
  графиков подписи утверждали «Цена, млн рупий» / «десятки миллионов
  рупий», хотя на график подавались нескейленные (сырые) значения
  `data['price']` — единицы на подписи не совпадали с реально
  отображаемым масштабом. Приведено к единому виду («Цена, рупии») везде,
  где данные не масштабируются; там, где код действительно делит на
  `1e6` (например, диаграмма разброса), подпись уже была верной и не
  менялась.
- **`HousingPrices.ipynb`, подпись моды на гистограмме цен** — текст
  `«Мода (0.35-0.4)»` был зафиксирован вручную и не совпадал с реально
  вычисленным интервалом моды (≈3.48–4.06 млн). Подпись теперь строится
  из фактического `price_mode.left`/`price_mode.right`.
- **`Finale.ipynb`, диаграмма Парето по классам кредита** — проценты
  дефолта (`default_rate`) переиндексировались по постороннему,
  никак не связанному с данными списку `custom_order`, а не по тому
  порядку (`default_counts.index`), в котором реально рисовались
  столбцы — из-за этого подписанный % на столбце мог относиться к
  другому классу кредита. Исправлено по аналогии с соседней строкой
  (`income_percent`), которая уже переиндексировалась правильно.
- **`Finale.ipynb`, тест Манна-Уитни (гипотеза №1)** — перед тестом
  обе группы (дефолт/не дефолт) искусственно урезались до одинакового
  размера («балансировка»). Это приём для борьбы с дисбалансом классов
  при обучении моделей, а не требование теста Манна-Уитни, который
  корректно работает и с разными размерами выборок — балансировка
  только выбрасывала часть реальных данных без необходимости. Тест
  теперь считается на полных группах.
- **Методологическое уточнение** (не код, а формулировка): фильтр,
  убирающий заёмщиков старше 35 лет / с доходом выше $100K и т.д.,
  наравне с очисткой от аномалий (возраст 144 года и т.п.) убирает и
  вполне реальных заёмщиков, сужая выборку на 27%. Итоговые выводы
  формально применимы только к этому суженному сегменту — теперь это
  явно оговорено прямо в ноутбуке (после фильтрации и перед итоговыми
  выводами).
- **Дублирующийся график** («по наличию кондиционера» повторялся дважды
  подряд в `HousingPrices.ipynb`) и **несколько пустых ячеек** —
  удалены.

⚠️ Так как перегенерировать графики без исходных CSV-файлов было
невозможно, у изменённых ячеек очищен вывод (`outputs`/`execution_count`).
**Перед публикацией на GitHub оба ноутбука нужно один раз перезапустить
целиком** (`Kernel → Restart & Run All` в Jupyter) — тогда все графики
пересчитаются уже с исправлениями.

### Осталось на усмотрение автора (не менялось, чтобы не трогать суть анализа)

- В блоке с t-тестом про парковку (`HousingPrices.ipynb`) переменные
  названы кириллицей (`дома_с_парковкой` и т.п.) — работает корректно,
  но не самый распространённый стиль; можно переименовать латиницей,
  если это важно для единообразия.
- Присвоение имён кластерам в `Finale.ipynb` (`replace_dict`) сделано
  вручную по номеру кластера от `KMeans` — при повторном запуске с
  другой версией `scikit-learn`/`random_state` номера кластеров могут
  перераспределиться, и подписи перестанут соответствовать данным без
  явной ошибки. Пояснение об этом добавлено прямо в ноутбук; более
  устойчивое решение — формировать описание кластера программно из
  `cluster_stats`, а не по индексу.

## Как запустить

1. `pip install -r requirements.txt`
2. Скачать датасеты и положить рядом с ноутбуками под теми именами,
   которые ожидает код:
   - [Housing Prices Dataset](https://www.kaggle.com/datasets/yasserh/housing-prices-dataset) → `Housing.csv`
   - [Credit Risk Dataset](https://www.kaggle.com/datasets/laotse/credit-risk-dataset) → `credit.csv`
3. Открыть `HousingPrices.ipynb` / `Finale.ipynb` в Jupyter и выполнить
   `Kernel → Restart & Run All`.

Сами CSV-файлы в репозиторий не включены (сторонние датасеты с Kaggle) —
см. `.gitignore`.
